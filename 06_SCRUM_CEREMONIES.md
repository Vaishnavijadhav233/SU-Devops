# 06 Scrum Ceremonies

## Sprint Planning

The team selects high-priority stories, discusses dependencies, estimates effort and agrees on the Sprint Goal.

## Daily Scrum

Each member reports what was completed, what will be done next and any blocker.

## Sprint Review

Completed features are demonstrated and stakeholder feedback is recorded.

## Sprint Retrospective

The team discusses what went well, difficulties and practical improvements for the next sprint.

## Definition of Done

- Feature is implemented according to the user story.
- Acceptance criteria are satisfied.
- Testing is completed and major defects are fixed.
- Code is integrated into the repository.
- Documentation is updated.
- Feature is demonstrated in Sprint Review.

## Sprint Review Report – Format

| Item | Details to Record |
|---|---|
| Sprint Goal | Whether goal was achieved |
| Completed Stories | Stories demonstrated |
| Not Completed | Stories carried forward and reason |
| Feedback | Suggestions from Product Owner/users |
| Action | Backlog changes or improvements |

## Sprint Retrospective Report – Format

| Question | Team Notes |
|---|---|
| What went well? | Communication, planned work, testing |
| What was difficult? | Dependencies, debugging, unclear requirements, time |
| What should improve? | Smaller tasks, earlier testing, clear ownership |
| Action for next sprint | One or two measurable improvements |
